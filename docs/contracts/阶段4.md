# 阶段 4 接口与派单

基线 62d8f11。取材范围是本机 Antigravity 2.34.0 的固定界面资源。所有译文重新编写。原始候选清单保留在临时目录。仓库只收录审核过的 UI 词条、位置和摘要。

| 负责方 | 产物 | 验收 |
|---|---|---|
| 提取工人 | internal/extractor 与 extract 开发子命令 | 只读扫描 ASAR 固定界面成员与 language_server 内嵌 ZIP 的 main.js，保留成员、字节偏移、原文和 SHA-256。可导出复核、比较两版候选。模拟安装测试可在两平台运行 |
| 界面词典工人 | core、workspace、settings、agents 四个 JSON，以及经过实证的固定 UI 叶节点 | 覆盖主界面、侧栏、设置、权限、新手引导、模型区；排除动态内容与用户名称，词条有据可查，统计可见边界 |
| 原生词典与校验工人 | menus_dialogs.json、locales 下的 Go 装载与一致性测试、固定原生文案适配 | 检查右键、菜单、托盘和弹窗；检查重复、模块归属、作用域、泛用短词、词典证据格式，提供可交给阶段 3 Build 的数据 |

每个 JSON 顶层为 schema（整数 1）、module（文件名去后缀）、version（2.34.0）、sources（成员标识至成员内容 SHA-256 的对象）、exact、scoped、templates（数组）。每条有 en、zh、source、offset。offset 从成员开头以 UTF-8 字节计，指向英文 JS 字符串的起始引号。scoped 条目另含 scope，模板另含 id 与带 {n} 的 zh，en 指可复核的官方原文。成员标识为 asar:dist/menu.js 等，或 hub:main.js。同一匹配层的键须唯一。

开发者可先只读分析，再用交付的提取器逐条重放证据。提取清单使用 {version,sources,entries}；entries 至少有 {en,source,offset}，校验以成员、字节位置和解码原文共同匹配。基础词典和用户词典分开合并，专有术语遵循用户最初给出的术语表。

## 在本机复核

在仓库根目录运行以下命令。输出写入当前目录下新建的报告目录。每次请使用尚不存在的输出目录。

```sh
go run ./cmd/antigravity-zh-gui extract --target /Applications/Antigravity.app --out ./automatic-report
go run ./cmd/antigravity-zh-gui extract --target /Applications/Antigravity.app --verify ./locales/zh-CN --out ./evidence-report
```

要比较两个版本，对新版运行第一条命令并加上 `--diff ./automatic-report/candidates.json`，同时更换输出目录。对比时两边应使用相同的提取选项。自动候选仅代表静态扫描找到的可能文案，同一英文可以在多处出现。证据重放还会检查人工审核选中的位置。
