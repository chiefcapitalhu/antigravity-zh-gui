# 阶段 2 独立复核

独立检查使用仓库源码、合成安装和临时目录。审查对象包括文件树及成员摘要、构建与提交之间的变更检测、签名失败和备份恢复路径，以及 Windows 专属探测与配置测试。

| 编号 | 复核中发现的问题 | 验收依据 |
|---|---|---|
| R1 | 固定的官方整包备份可被显式选作普通汉化目标，再次重签会破坏恢复来源 | 对备份自身请求汉化应在修改前拒绝，同一目录的别名也要覆盖 |
| R2 | macOS 交换整个包目录，原有提交前检查仅比较 ASAR 和 Info.plist | 构建期间其他包成员发生更新时，旧副本不得覆盖更新 |
| R3 | 未建基线的新版本仅凭模块内一行英文命中，可能替换其他位置的同一句文案 | 上下文迁移或锚点缺失时应返回明确提示并保留原件 |
| R4 | 先规划成员、后获取源摘要，二者之间的软件更新可能将旧成员写入新归档 | 规划和重写须绑定同一份经过摘要校验的来源 |
| R5 | 原包成员缺少可选 integrity 时，逆向白名单审计可能拒绝完整还原 | 恢复一个原本没有成员摘要的归档，结果与原件逐字节相同 |

R1–R5 的修复已复核。R1 使用保留路径检查和文件身份判断；R2 摘要包含包内路径、模式、链接目标与文件内容；R3 校验更新对话框结构及两条原生展示分支；R4 在校验过摘要的私有快照上重新规划；R5 核对候选与原包整体摘要，再转换审计报告的前后方向。上述五项在 macOS 下的回归及竞态检查均通过。

Windows 缓存清理增加了原生 NTFS 目录联接测试，覆盖缓存根、分区及缓存内部目录三种位置。测试会核对目录外的哨兵文件内容，创建联接失败会让用例失败。该测试已通过跨平台静态检查，运行结果由 Windows CI 提供。

持续集成使用 Windows 与 macOS 原生托管运行器，执行 Go 1.22 的依赖清单检查、静态检查、单测与构建。源码显示 Windows 原生测试通过临时目录创建模拟安装和进程，验证默认路径、APPDATA、进程快照和残留语言服务识别。本机完成 YAML 语法检查、Windows amd64 静态检查及交叉构建。已核对实现提交 82dc2a2 的 [Windows 原生作业](https://github.com/chiefcapitalhu/antigravity-zh-gui/actions/runs/45050532005/job/137294425094) 和 [macOS 原生作业](https://github.com/chiefcapitalhu/antigravity-zh-gui/actions/runs/45050532005/job/137294424667)。二者均通过。Windows 日志包含全部三项目录联接测试及部分匹配、全部跳过和还原回归。
