# 阶段 5 命令行与共享服务

默认运行打开本地控制台。`--version` 输出工具版本，打包时可以用 Go 链接器的 `-X antigravity-zh-gui/internal/app.Version=版本号` 指定发布版本。命令行和控制台使用同一个 `internal/app.Service`，调用同一套安装探测、配置、词典校验和补丁事务。

| 操作 | 结果 |
|---|---|
| `status --target 路径` | 输出安装根目录、版本、系统、进程状态、汉化标记、归档备份和整包备份的存在状态，以及签名检查结果。无法确定的进程或汉化状态为 null，并附诊断信息 |
| `apply --target 路径 --hotkey=true --default-lang=zh --brand=keep` | 合并已存偏好和本次显式选项，读取本地自定义词条，再调用本地化事务。显式选项仅影响本次操作 |
| `verify --target 路径` | 只读比较基线与当前安装，输出文件数量和改动文件的大小及 SHA-256 |
| `restore --target 路径` | 从归档备份还原英文资源 |
| `restore --target 路径 --backup-app` | 在 macOS 从此前通过 `apply --backup-app` 创建的整包备份恢复官方签名，再次核验发行方签名及版本 |
| `extract --help` | 查看阶段 4 的只读提取、证据复核和版本对比选项 |

命令行输出 JSON 报告，步骤和用时输出到标准错误。未命中的规则保留源文件并返回 warnings。命令行未指定目标时优先使用已保存的安装路径，空路径交给平台自动探测。指定副本时，补丁器只处理该副本并保留用户缓存。实际还原时会校验备份；状态报告中的备份字段仅反映本地文件类型及是否存在。

测试使用临时模拟安装，覆盖已保存目标、签名未知状态、无匹配锚点、无法确认进程状态时拒绝写入、无效 CLI 参数、原有提取功能和自定义词条校验。

macOS arm64 / Go 1.22.12 已运行 `go vet` 和 `go test -count=1 -cover`，命令行、共享服务、安装检测三个包均通过。Windows amd64 目标的 `go vet` 通过。直接运行 `go run ./cmd/antigravity-zh-gui --version` 得到 `0.1.0`。

阶段 5 独审发现，两个控制台同时保存不同的个人词条时可能覆盖对方。现在每个请求只提交单个词条的增删。配置层在用户配置目录通过 `custom_dict.lock` 获取内核锁，取得锁后重新读取、修改并原子保存词典，进程退出时锁由系统释放。在本机对八个独立进程同时经控制台提交的 112 条词条逐一复核，全部保留。常设回归还验证了持锁进程退出后，其他进程能继续新增、更新和删除词条。
