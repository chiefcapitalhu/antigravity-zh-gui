# 阶段 5 双语运行时与桌面宿主接线

验收基线为本机 2.34.0。只读使用 `Contents/Resources/app.asar`，候选与 JavaScript 语法检查文件均写入临时目录。正式程序通过 `patcher.Apply` 将偏好与用户词条交给五模块词典。自定义文本经过 JSON 序列化，目标路径与整包备份选项仅供 Go 使用。

| ASAR 成员 | 固定展示位置 |
|---|---|
| dist/preload.js | 经过宿主身份确认的本地 Hub 顶层文档，双语切换和右键菜单展示 |
| dist/main.js | 本地界面身份与语言通知、退出和启动弹窗、Dock 与托盘固定菜单项 |
| dist/menu.js | 应用菜单、缩放、WSL 项和语言切换后重绘。更新动作按独立保存的原始英文状态执行 |
| dist/tray.js | 托盘菜单与动态助手数量 |
| dist/updater.js | 手动检查更新结果及更新动作的显示状态 |

补丁器核对固定成员 SHA-256（接受统一的 Windows 换行），逐处检查替换锚点恰好出现一次。它也只读核对本地窗口注册表、端口和后端身份判定所依赖的四个成员。宿主要求现有客户端认可发送方为本地 Hub 顶层，并核对活动语言服务端口与发送帧的 HTTPS 回环来源。预加载脚本不向网页暴露语言设置接口。原生侧仅接收两种语言值。应用、托盘、Dock 和可见 DOM 的控件均通过已审核的展示代码更新。

界面、主进程和菜单通过同一组固定接口同步语言。该组无法完整匹配时会给出警告并保留主界面原样，对仍能唯一识别的手动更新弹窗及 Windows WSL 启动提示进行独立处理。托盘与更新模块均可单独跳过。更新模块未知时，其菜单项沿用客户端英文状态以保留原有的点击分派。SSH 窗口、外部来宾页面、操作系统自行生成的文案和动态用户内容遵循各自的展示边界。

构建回执绑定安装路径、原包与已通过白名单审计的完整候选摘要。补丁更新和英文还原均从纯净备份进行。新版候选同时在标记内记录显示偏好与个人词条的 JSON；资料移动后，本版本可从原始备份与该 JSON 重建，逐字节验证全部修改。旧版固定弹窗补丁仍可识别。真实安装包及用户会话未用于写入测试。

本机使用 Go 1.22.12 对实际 ASAR 构造候选。五个白名单成员均命中，所有候选 JS 通过 Node 语法检查，Go 对比审计仅报告这五个成员。测试覆盖固定 IPC 的宿主身份与模式通知、菜单与托盘切换、动态更新动作、无回执时重新验证、平台差异回退、重新应用和还原。其他机器可通过已有的 Go 测试复核模拟宿主；额外设置 `AGZH_UI_SAMPLE_ASAR` 指向只读 2.34.0 样本时还会运行真实资源的候选检查。真实副本及托管 CI 的结果由阶段 5 总验收记录。
