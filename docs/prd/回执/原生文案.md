# 阶段 3 原生文案与打包回执

基线为 418583c。实现位于 runtime/main_hooks.js 与 runtime/assets.go。词条由宿主作为数据传入，本轮采用合成词典验收。

| 文案入口 | 定位与行为 |
|---|---|
| 应用菜单 | 本机 2.34.0 的 dist/menu.js 通过 check-for-updates、hub-reset-zoom、hub-zoom-in、hub-zoom-out 等 ID 定位。更新动作以英文状态分派，每次从原始模板重建展示副本时保存该状态。两种动作翻成同一个名称时也能正确分派。 |
| Dock 与托盘 | 对应 dist/main.js 中固定的 Dock 新窗口、托盘打开和退出构造点，宿主可调用 siteLabel。dist/tray.js 的 running-agents 项按原始计数文案匹配，保留数值。 |
| Hub 右键菜单 | 官方前端传递有语义的命令 ID，缺少 ID 时生成位置编号。wrapShowContextMenu 包装指定的宿主方法，保持原接收者、返回的 Promise 和选中项 ID。仅翻译已核对的 ID 与英文原文，位置编号及未知子菜单保留原样。 |
| Sidecar 外壳 | 本机 Hub 组件中可见 sidecar-action-view-logs 等固定 test ID。label 可按这些 ID 查询外壳控件文案，插件名称及子框架内容由宿主保留。 |

**接线。** Go 的 Build 接受探测平台、偏好和结构化词典。它输出包含固定 JS 工厂及 JSON 数据的 HubFactory 和 NativeFactory。宿主创建原生展示对象时指定重建回调，应用启动、模式改变或菜单状态更新时用当前的英文模板重建。HubFactory 需要由专用宿主确认本机 Hub 身份，提供其已知本机来源与顶层身份；函数再核对窗口与 origin。宿主以 onModeChange 将语言枚举交给原生对象的 setMode。真实 Electron 跨进程的事件传递和菜单重建需在客户端接线时实现。本轮验证使用隔离的合成宿主。

**已执行。** Node 原生回归验证了上下文菜单返回值和接收者、更新动作分派、托盘计数、Dock 与 Sidecar 规则。Go 测试实际运行嵌入工件，覆盖语言偏好同步、同窗口重复安装、来源及子框架拒绝、文字转义、平台归一化和泛用词限制。命令为 `node --test tests/native.test.cjs` 与 `go test -v ./runtime ./internal/config`。
